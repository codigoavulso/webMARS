01

Automatic session heartbeat

On the official installation, a separate background ping sends cumulative active seconds every 60 seconds while the app is visible, including when another tab or window has focus. Each page load uses a random memory-only session token; the collector stores only a one-way hash, an approximate duration and a registered/not-registered classification. It uses no account ID, email, cookie or persistent visitor ID. The supplied endpoint does not log IP addresses. Sessions seen within the last five minutes are counted as active-session estimates; this is not a count of people and can under-count suspended or offline browsers. Network transport still exposes an IP address to the host.

02

What the statistics contain

A random temporary visit token, page category, compiler/assembler/execution outcomes, shipped tool identifiers, use of stepping, projects, Cloud and help, built-in lesson numbers, approximate active seconds, interface language, touch/pointer input category and a broad acquisition category. No source code, inputs, output, project names, account IDs, emails, full URLs or raw referrers are included.

03

Automatic collection and browser storage

Statistics are sent automatically, independently of interface settings, Do Not Track, Global Privacy Control or an earlier statistics choice. There is no statistics checkbox or acceptance dialog. A token in sessionStorage groups events in this tab and expires after 30 minutes without measured activity. A local last-visit timestamp supplies a coarse return category. If storage is unavailable, events use a memory-only token; reloads then create new visits and returns cannot be measured. There is no persistent visitor ID. Network or browser blocking can still prevent delivery.

04

Time and retention

Interaction time requires a visible, focused page with interaction in the last minute; it is sampled every five seconds and sent roughly every 30 active seconds. Presence heartbeats have the separate timing rules below. The collector retains statistics for 35 days. Counts describe measured visits and feature adoption, not unique people, exact attention or verified learning outcomes. Temporary session tokens allow events to be linked within a visit; calling them statistics does not remove that linkage.

05

Server logs and Cloud are separate

The host receives your IP address to serve requests. The supplied metrics endpoint does not store it, cookies or raw browser headers. Ordinary access logs may contain IP addresses and browser information; the documented Raspberry Pi logging policy retains those logs for up to 370 days. Cloud sign-in, synchronization and publication are optional and transmit the data required for those operations to the configured BackMars server.

06

What the operator can analyse

Daily visits, acquisition, languages and devices, feature adoption and observed duration distributions. Different tabs and cleared storage can count the same person more than once. Historical periods used different collection rules; enabling broader collection can increase counts without proving audience growth.
