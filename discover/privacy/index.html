01

Automatic session heartbeat

On the official installation, a separate background ping sends cumulative active seconds every 60 seconds while the app is visible, including when another tab or window has focus. Each page load uses a random memory-only session token; the collector stores only a one-way hash, an approximate duration and a registered/not-registered classification. It uses no account ID, email, cookie or persistent visitor ID. The supplied endpoint does not log IP addresses. Sessions seen within the last five minutes are counted as active-session estimates; this is not a count of people and can under-count suspended or offline browsers. Network transport still exposes an IP address to the host.

02

What optional metrics contain

A random tab-session ID, a page category, general actions such as assembly or successful execution, a built-in lesson number, approximate active seconds, interface language, touch/pointer input category and a broad source category (direct, search, social, internal or other). No source code, inputs, output, project names, account IDs, full URLs or raw referrers are included.

03

What is stored on this browser

Your yes/no choice is saved locally. After accepting, a session ID is stored for this tab and expires after 30 minutes without measured activity. A last-visit timestamp supplies a coarse return category: same day, 1–6 days, 7–30 days or older. There is no persistent visitor ID. Turning collection off clears that session and timestamp; clearing site data resets the choice. Do Not Track and Global Privacy Control disable collection.

04

Time and retention

Active time is approximate: only a visible page with interaction in the last minute is counted, including when another tab or window has focus, with updates roughly every 30 active seconds. The automatic presence counter counts sessions seen in the last five minutes, not people. It uses a random per-session token and a registered/not-registered classification; no account ID, email or persistent visitor ID is stored by the collector. Network failures and blockers can lose events. The supplied collector keeps events for 35 days and sends them to this installation only. Revoking consent stops new events; existing records expire with retention.

05

Server logs and Cloud are separate

The host receives your IP address to serve requests. The supplied metrics endpoint does not store it, cookies or raw browser headers. Ordinary access logs may contain IP addresses and browser information; the documented Raspberry Pi logging policy retains those logs for up to 370 days. Cloud sign-in, synchronization and publication are optional and transmit the data required for those operations to the configured BackMars server.

06

How to choose

When the operator enables metrics, use the permanent Usage statistics control on the public pages or in the simulator. If that control is absent, optional usage metrics are disabled for this installation. The app works without accepting. Metrics cover consenting tab sessions, not all visitors, unique people or verified learning outcomes.
