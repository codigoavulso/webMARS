## What is compared

Both simulators assemble and run the same source under equivalent settings
(start at `main`, default memory map, 100 000 step limit), and four
observable results are compared:

| Result | How |
| --- | --- |
| Text segment | MARS `dump .text HexText` versus the machine code webMARS reports per row, word for word |
| Data segment | MARS `dump .data HexText` versus words read back through the webMARS engine |
| Console output | Everything the program wrote, in order |
| Final registers | All 32 general-purpose registers, minus the exclusions below |

Diagnostics are compared separately and by *line*, not by wording - see the
exceptions.

## Rules for intentional differences

A difference is a defect unless it appears below. Adding an entry requires a
reason that would satisfy a reader who did not write the code - "webMARS does
it differently" is not one.

### `diagnostic-wording` (diagnostics)

Diagnostic wording differs; the rejected line must still match.

**Why this is accepted:** webMARS messages are translated into twenty languages, so they cannot be byte-identical to the English originals. The comparison checks that both simulators reject the same source and blame the same line.

### `volatile-scratch-registers` (registers)

$at, $k0 and $k1 are excluded from the register comparison.

**Why this is accepted:** $at is assembler scratch whose residue depends on which pseudo-instruction expanded last; $k0 and $k1 belong to the exception handler. Neither is a defined result of a user program.

### `stack-pointer-base` (registers)

$sp, $fp and $gp are compared as deltas from their initial value, not absolutely.

**Why this is accepted:** The absolute stack and global pointers come from the memory map, which is configurable. What a program is entitled to rely on is how far it moved them, not where they started.

### `li-32bit-preserves-at` (encoding)

A 32-bit `li` expands without using $at, so the two `lui`/`ori` words differ.

**Why this is accepted:** MARS expands `li $t0, 0x12345678` as `lui $at, 0x1234` + `ori $t0, $at, 0x5678`, which destroys $at. webMARS expands it as `lui $t0, 0x1234` + `ori $t0, $t0, 0x5678`, which leaves $at untouched. Both leave the same value in the destination; the instruction count is the same, so no address moves. Verified on tests/differential/cases/case-li-clobbers-at.asm: after `li $at, 999` followed by a 32-bit `li`, MARS reports $at = 305397760 and webMARS reports 999. Keeping $at intact is a deliberate choice - it makes the register usable by hand-written code - and reverting it would be a downgrade, not a fix.

**Minimal case:** `tests/differential/cases/case-li-clobbers-at.asm`

### `ble-immediate-cannot-overflow` (encoding)

`ble`/`bge` against an immediate expand to a sequence that cannot trap.

**Why this is accepted:** MARS expands `ble $t0, 5, label` as `addi $at, $t0, -1` + `slti $at, $at, 5` + `bne`. The leading `addi` traps on signed overflow, so the comparison itself raises an exception when $t0 holds -2147483648. webMARS expands it as `addiu $at, $zero, 5` + `slt $at, $at, $t0` + `beq`, which cannot overflow. Verified on tests/differential/cases/case-ble-immediate-min.asm: MARS terminates with "Runtime exception at 0x00400004: arithmetic overflow" while webMARS evaluates the comparison and prints 1. A comparison that traps on a legal input is a defect in the expansion, so webMARS does not reproduce it.

**Minimal case:** `tests/differential/cases/case-ble-immediate-min.asm`

## Limitations

- The corpus is 11 programs. It covers arithmetic, logic, shifts,
  comparisons, branches, memory widths, multiply and divide, function calls,
  pseudo-instruction expansion, data directives and console output. It is not
  the whole instruction set, and passing it does not mean full compatibility.
- Floating point, file syscalls, interactive input, MMIO devices and the
  exception handler are not compared here: they need input or a device the
  command-line MARS does not provide.
- Timing is not compared at all. MARS does not model it, and webMARS models it
  only in the Pipeline Lab. See [pipeline-lab.md](pipeline-lab.md).
- This report describes one commit. It is regenerated per release; see
  [release-process.md](release-process.md).
