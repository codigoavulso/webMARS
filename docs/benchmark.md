# webMARS benchmark

Generated by `scripts/benchmark.mjs` for webMARS 0.6.0.
Regenerate with `npm run benchmark`. Do not edit this file by hand.

## Protocol

A number without its protocol cannot be compared to anything. This one is:

| Parameter | Value |
| --- | --- |
| Protocol version | 2 |
| Warm-up runs (discarded) | 3 |
| Measured repetitions | 7 |
| Outlier handling | discard the single fastest and single slowest measurement, then report the median and interquartile range of the rest |
| Statistic reported | median with interquartile range (IQR) |
| Timer | process.hrtime.bigint(), nanosecond resolution |
| Timed window | operation under test only; engine creation and per-sample reset/assembly are excluded unless assembly is the operation under test |

Medians and interquartile ranges are reported rather than means. On a machine
with other work running, a mean over a handful of runs describes the scheduler
more than the code. The IQR is the dispersion figure: a large IQR means the
median is not a reliable summary and the run should be repeated on a quiet
machine.

## Workloads and what each answers

- **`assemble-small`** (assembly) - Cost of assembling a short program - the latency a student feels on every Assemble press.
- **`assemble-large`** (assembly) - Whether assembly scales linearly. A quadratic pass shows up here and nowhere else.
- **`execute-tight-loop`** (execution) - Steady-state interpreter throughput on register-only work.
- **`execute-memory-bound`** (execution) - Throughput when every iteration touches memory, which exercises the slower path.
- **`execute-with-tool`** (tools) - Cost of a real instruction-observer integration: the same execution with a snapshot read every 64 retired instructions.
- **`compile-mini-c`** (compilation) - Cost of compiling Mini-C to MIPS, the step before assembly in the C workflow.

## Running it yourself

```bash
npm run benchmark
```

The protocol above is applied exactly as published. To compare against these
figures, run it on a quiet machine and compare medians and IQRs, not single
measurements.

## Limitations

- These are **Node.js** measurements. The application runs in a browser, and
  the browser adds rendering, event handling and its own JIT behaviour. Node
  numbers bound the engine's cost; they do not predict the interface's.
- Browser automation is not part of this script. Chrome and Firefox figures
  are not published yet, so no cross-browser claim is made here.
- The Mini-C workload measures compilation only, not the assembly or execution
  that follows it.
- Nothing here measures the Pipeline Lab, which is a timing model rather than an
  execution engine and has no wall-clock claim to make.
