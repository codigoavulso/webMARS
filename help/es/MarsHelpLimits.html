Límites y compatibilidad

webMARS busca compatibilidad práctica con fuentes MARS 4.5 ejecutándose íntegramente en un navegador moderno. Se aplican las reglas de seguridad, almacenamiento y audio del navegador.

Límites del runtime

ÁreaLímite o comportamiento
Memoria0,25–2 GiB seleccionables, con techo arquitectónico por debajo de 0x80000000. La asignación dispersa evita reservar cada byte sin usar.
Heapsbrk valida la reserva completa antes de mover el puntero y no puede desbordar el límite.
Paso atrás0–1.000.000 instantáneas; valores altos pueden consumir mucha memoria.
Almacenamiento del navegadorSujeto a cuota. La aplicación limita a 1 MiB determinadas cargas guardadas y usa recuperaciones más pequeñas cuando es necesario.
TemporizaciónSleep, MIDI y la interfaz usan el planificador del navegador y no son exactos por ciclo.
DistribuciónwebMARS 0.4.7 es una aplicación web estática, no una PWA instalable u offline. Debe servirse por HTTP con el servidor local incluido u otro host estático.

Comportamiento MIPS

  • La memoria es little-endian. Las operaciones de palabra y doubleword respetan el orden MIPS.
  • Los fetch desalineados y las direcciones inválidas generan excepciones de dirección.
  • Una escritura comprueba todo el destino antes de modificarlo y nunca deja un valor parcial.
  • LL/SC usan una reserva que invalidan las escrituras conflictivas.
  • Las conversiones COP1 respetan FCSR y las entradas numéricas rechazan texto sobrante.
  • En modo estricto, también las cargas parciales como LWL y LWR deben estar en segmentos permitidos.

Límites de portabilidad

  • El sistema virtual de archivos no es el sistema de archivos sin restricciones del host.
  • Los permisos de audio pueden afectar a los syscalls MIDI.
  • Las políticas de popups y descargas pueden afectar a las exportaciones.
  • Mini-C solo acepta sus perfiles documentados, no todo ISO C ni una libc completa.
  • No están disponibles extensiones históricas basadas en clases Java o plugins de escritorio.
