Exceptions

A runtime fault either transfers control to the configured exception handler or terminates the run with an explicit reason. Handled exceptions can continue through eret.

Handler flow

  1. The runtime captures Cause, EPC and BadVAddr as appropriate and enters exception level.
  2. If executable handler code exists at the configured address—normally 0x80000180—the PC transfers there.
  3. The handler inspects COP0 state, performs its recovery, adjusts EPC when required, and executes eret.
  4. If no handler is present, or an exception occurs that cannot be transferred safely, execution halts and the Run result reports the exception.
Delay slots. For an exception raised in a branch delay slot, Cause.BD is set and EPC identifies the branch instruction, not the delay-slot address.

Address and store guarantees

Instruction targets must be word-aligned. Checked multi-byte stores validate the whole destination before committing any byte, so an address exception cannot leave a partially written word or doubleword. Strict memory mode also applies to partial-word operations such as LWL and LWR.
