Limits & compatibility

webMARS aims for practical MARS 4.5 source compatibility while running entirely in a modern browser. Browser security, storage and audio rules still apply.

Runtime limits

AreaLimit or behavior
MemoryUser-selectable 0.25–2 GiB, with an architectural hard ceiling below 0x80000000. Sparse allocation means untouched address space is not committed byte-for-byte.
Heapsbrk validates the full unsigned reservation before changing the heap pointer. Requests cannot wrap or bypass the configured memory ceiling.
Runtime stringsNull-terminated strings can contain up to 1 MiB. A missing terminator or a longer string raises an explicit syscall error instead of returning truncated text.
Backstep0–1,000,000 inverse deltas. History is bounded by the configured budget while always retaining the latest 100 complete steps when backstep is enabled.
Browser file storageProject/session data is subject to browser quota; the app limits user browser-storage payloads to 1 MiB where applicable and falls back to smaller recovery payloads if needed.
Run timingSleep, MIDI and UI timing are scheduled by the browser and are not cycle-accurate.
DistributionwebMARS 0.5.3 is a static web application, not an installable/offline PWA. It must be served over HTTP by the included local server or another static host.

Compact Data and Compact Text presets move the corresponding teaching segments to address zero. Reassemble after changing maps.

MIPS behavior

  • Memory is little-endian. Word and doubleword operations use MIPS register/memory ordering.
  • Misaligned instruction fetches and invalid load/store addresses raise address exceptions.
  • Stores validate the complete destination before writing, so a failing store does not leave a partial value behind.
  • LL/SC use a reservation that conflicting stores invalidate.
  • COP1 conversions honor FCSR rounding modes; floating-point input rejects trailing non-numeric text.
  • With strict MARS compatibility, memory operations—including partial-word loads—must remain inside permitted segments.

Known portability boundaries

  • The browser virtual file system is not the host operating system's unrestricted file system.
  • Web audio permission and autoplay policy can affect MIDI syscalls.
  • Popup blockers and download policy can affect exported files.
  • Mini-C accepts its documented profiles only; code relying on full ISO C, a host libc or undefined behavior is not portable to it.
  • Historical MARS extensions that depend on Java classes or desktop plug-ins are not available.
