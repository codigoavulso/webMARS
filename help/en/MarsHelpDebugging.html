Run & debug

The Run menu controls one JavaScript MIPS engine shared by the registers, memory views, debugger and connected tools.

Execution controls

ControlMeaning
GoRuns until normal completion, a breakpoint, a syscall waiting for input, an unhandled exception, a limit, Pause or Stop.
PauseSuspends an active run while preserving the machine so it can continue.
StopTerminates execution and cancels pending asynchronous work such as a long Sleep syscall. A stopped program does not resume.
StepExecutes one instruction. After a breakpoint stop, the next Go or Step crosses that breakpoint once, so it does not immediately stop at the same address again.
BackstepRestores the previous recorded runtime snapshot, up to the configured history depth.
ResetReturns the assembled program to its initial machine state.

Breakpoints and source tracking

Toggle a breakpoint in the editor gutter beside an executable source line. Breakpoints are stored in runtime state and survive the normal export/import round trip. Pseudo-instructions may expand into several basic instructions; stepping follows the generated machine instructions while source highlighting remains associated with the originating line.

Speed and performance strip

The run-speed control ranges from interactive stepping rates to maximum speed. At maximum speed webMARS reduces expensive editor highlighting and auto-scroll work, but tools continue to receive complete runtime snapshots and trace information.

The compact benchmark strip reports recent Compile, Assemble and Run timing together with an estimated JavaScript CPU utilization percentage. Measurements are local and volatile: they are intended for comparing workloads and algorithm changes, not as an operating-system process meter.

Delayed branches and exceptions

When delayed branching is enabled, the instruction following a branch or jump is the delay-slot instruction and link instructions store PC + 8. Exceptions raised in a delay slot set the COP0 Cause BD bit and record the branch address in EPC.

If a valid exception handler exists at the configured handler address, execution transfers to it and may return with eret. Otherwise the run stops with an explicit reason and diagnostic.

Backstep scope. Snapshots include registers, memory, breakpoints, random streams, file positions, pending input, program arguments and device image handles. Large histories consume memory, so tune the limit to the exercise.
