Settings

Settings cover source presentation, assembler compatibility, Mini-C output, persistence, cloud access and runtime limits.

Assembler and execution compatibility

  • Assemble on open and Assemble all files automate the selected build scope.
  • Treat warnings as errors makes warnings fail assembly.
  • Start at main begins at the global main label when present.
  • Extended (pseudo) instructions enables the pseudo-instruction catalogue shown in Help.
  • Delayed branching enables architectural delay-slot behavior.
  • Self-modifying code permits writes to executable memory. Enable it only for programs that intentionally require it.

Interface

Select the interface theme (Light or Dark), the UI language, top or side menu layout, editor font size, line spacing and highlighting behavior. English, Spanish, Portuguese, Mandarin Chinese, Hindi, Arabic, French, Bengali, Russian and Indonesian interfaces are available; help follows the active UI language. On the first visit, webMARS uses a supported browser language or falls back to English; an explicit selection is saved and takes priority. The chosen theme is stored with your preferences and is applied to the whole interface, including tool and help windows.

Persistence and cloud

Store state and Load state manage a complete local runtime snapshot. Clear localStorage removes webMARS preferences, saved projects, recovery state and tool positions after confirmation.

Cloud Server changes the endpoint used by the optional Cloud menu. Credentials and project data are sent only when you invoke cloud features.

Changing the memory map or assembler compatibility options invalidates assumptions made by an already assembled program. Reassemble after changing them.
