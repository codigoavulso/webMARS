History

webMARS began as a browser port of the MARS 4.5 MIPS simulator. It now combines an independent JavaScript runtime, editor, debugger, Mini-C compiler, local/cloud project workflows and browser-native tools.

Current development line

  • JavaScript-only runtime. The experimental hybrid/WASM path was removed after measurement showed that it added complexity without a worthwhile improvement for this workload.
  • Runtime correctness. Recent work hardened doubleword COP1 ordering, atomic memory stores, heap reservations, LL/SC, strict addressing, delayed-branch links, FCSR rounding, exception continuation and Stop behavior.
  • Complete state snapshots. Export/import and backstep now account for random streams, virtual files and cursors, stdin, program arguments, image handles and breakpoints.
  • Performance observability. The app reports local Compile, Assemble and Run timings plus estimated JavaScript utilization, while maximum-speed execution reduces presentation overhead without starving tools of runtime state.
  • Mini-C evolution. C0 teaching subsets remain available alongside C1-NATIVE, o32 calls, byte strings, arguments, function pointers, multi-file projects and compatibility libraries.
  • Examples as a curriculum. Assembly and C examples are catalogued by purpose, language and minimum compiler profile, with multilingual variants and multi-file projects.

Compatibility lineage

The instruction vocabulary, common syscalls, user interface concepts and teaching model derive from the original MARS project by Pete Sanderson and Kenneth Vollmar. webMARS preserves that lineage while replacing Java desktop integration with browser APIs and its own execution engine.

Version record

The webMARS → Changelog help page contains the detailed version-by-version project record. Historical entries describe the state of their release; they are not promises that an experimental subsystem remains in the current build.

When documentation and a historical changelog entry differ, the current topic pages and current runtime behavior take precedence.
