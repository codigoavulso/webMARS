Changelog

Release 0.6.3 makes usage statistics public in the app and makes published projects easier to explore.

0.6.3 — public statistics and project discovery

  • Added an integrated Usage statistics window with charts for the last 60 minutes, 24 hours and 30 days, customizable filters and exact-value tables.
  • Published aggregate-only usage data without session identifiers, separating interaction time from visible presence.
  • Made the Public Library searchable and paginated, with a detailed project list instead of a selection dialog.
  • Expanded automatic usage metrics and linked heartbeat samples to the same temporary session as other events.

0.6.2 — public learning pages and duration metrics

  • Added public English and Portuguese discovery pages for the product overview, learning path, teaching, stack, pipeline, Mini-C and privacy.
  • Added a duration-only background heartbeat that reports cumulative active seconds without identifiers, cookies or stored session data.
  • Added the Raspberry Pi aggregate collector and deployment configuration for the heartbeat, with access logging disabled for its endpoint.
  • Documented the public pages, metric interpretation, retention and deployment order, while keeping richer event metrics disabled by default.
  • Extended release validation and packaging to cover the new pages, heartbeat and collector tests.

0.6.1 — complete packages and hardened stable links

  • Bundled the independently versioned Manual and Teacher Kit in the deployment ZIP, eliminating the dead /manual/ link in fresh installations.
  • Made the permanent example-ID registry authoritative: valid redirects still resolve, while tombstones, unknown IDs and redirect loops fail closed.
  • Made Public Library pagination follow BackMars's explicit hasMore result while retaining compatibility with older installations.
  • Corrected light and dark theme contrast in the application and Manual, and gave dialog messages an accessible name.
  • Extended release validation to the bundled Manual, its product-lock hashes, JavaScript modules and internal links.
  • Corrected localized product information to report the 20 tools actually shipped.

0.6.0 — stable classrooms and a public library

  • Added permanent direct links for every built-in example. Stable IDs live in a dedicated registry and are never removed or reused; retired entries remain as tombstones or explicit redirects.
  • Added public project publishing through BackMars. Every publication receives a globally unique public name on that deployment, on a first-come basis, and opens through a short /p/name link.
  • Made published revisions immutable. The unpinned link follows the newest active revision, while /p/name@N keeps opening the exact historical snapshot even after an ordinary archive.
  • Added a Public Library browser with search, paging and read-only previews. Opening a publication creates a clean local copy, so public material never silently changes the author's project or enters Cloud storage.
  • Versioned and sanitized the public interchange format. Publications contain only the project files and safe teaching metadata, with strict limits enforced independently by the browser and BackMars.
  • Added password recovery by email using expiring single-use codes. A successful reset invalidates existing sessions, and requests do not reveal whether an address is registered.
  • Added email verification and resend flows. Deployments may require a verified address before publishing while keeping local editing, examples and simulation available without an account.
  • Moved each installation's name, base path, public URL, BackMars endpoint, manual and support links into webmars-config.js, so universities can deploy independent instances without editing application code.
  • Replaced the automatic first-run About window with a guided Welcome window, while keeping About under Help and giving direct example or publication links priority.
  • Added a Teacher Kit covering migration from MARS, a first class, LMS text, stable-link publishing, solutions and self-hosting/privacy decisions.
  • Started the independently versioned webMARS Manual at v0.1, with detailed chapters, light-theme screenshots and explicit verification against a webMARS release.
  • Added production guidance and route configurations for stable URLs, private database storage, backups, migrations, Gmail SMTP and post-deployment smoke tests.

0.5.6 — the pipeline follows the program

  • Added a recorded-execution stream to the Pipeline Lab. Instead of assuming how a branch resolved, the model replays the sequence webMARS really executed, so taken branches, mispredictions and discarded instructions are facts rather than assumptions.
  • Added the Registers view: the value of every register at the current cycle, the values still in flight in an earlier stage, and a grid of every register against the cycle that changed it. A value only appears where the runtime supplied one; the static stream deliberately shows none.
  • Linked the two transports. One instruction executed in webMARS is one instruction entering the pipeline, in both directions: Step and Backstep in the main window move the pipeline, and the tool's own step controls run or un-run the program when the fetch stage has nothing left to read.
  • Added F8 for Backstep, which had no shortcut while Step had F7.
  • Redrew the Pipeline Lab as a vertical pipeline with the pipeline register between each pair of stages, beside the timeline rather than above it, so a stage can show the instruction, its source line and the values it used.
  • Made the Pipeline Lab lay itself out against its own window rather than the screen, so a narrow window on a large display folds the same way a phone does, and every control group can be opened and closed by hand.
  • Added a targeted locale updater that translates only the strings a catalog still answers in English, without rewriting entries already corrected by hand. It refuses any translation that changes a placeholder.
  • Translated 872 interface strings that were still shown in English across seventeen languages, and added a test that fails when a language answers more of the interface in English than it did before.
  • Fixed the Pipeline Lab ignoring Backstep in the main window: the runtime delivers it on a channel the tool was not listening to, so the tool kept replaying instructions that had been un-executed.
  • Fixed stepping in mobile mode replacing whatever panel the reader had chosen. Focus caused by running the program no longer changes the visible panel; opening a window, new or already open, still does.
  • Fixed the Pipeline Lab showing only the last stage while following a stepping program, which made the pipeline drain and refill on every step instead of filling up.
  • Fixed three interface colour tokens that were never defined, which silenced the stall marker in the timeline and left muted text unmuted in both themes.
  • Fixed a replay stalling until it ran out of cycles when the recording jumped somewhere no branch predicted, such as a program reset or an exception handler.
  • Added npm run version:set, which writes the version to all eleven places that declare it, and moved the version out of the help pages that state it into the runtime token.
  • Rebuilt the Pipeline Lab timing model: control hazards, configurable delay slots, static and dynamic branch prediction, configurable memory latency, serialised traps, and seven individually versioned architectural profiles that can be compared side by side.
  • Added the Architecture view, drawing the datapath with pipeline registers, per-instruction control lines, multiplexers, live forwarding paths and hazard detection, with signal groups that can be hidden individually.
  • Added a branch history table shared with the BHT Simulator, so both tools predict identically; a regression test drives the two predictors through the same outcome sequences and fails on any divergence.
  • Added reproducible JSON and CSV export carrying the model version, profile version, full configuration and a hash of the program, with no timestamps, so the same work produces a byte-identical file.
  • Added seven guided laboratories with objectives, prerequisites, a predict-before-you-run step and reflection questions, plus separate solution sheets, a teacher adoption guide and a short presentation. Every number a worksheet quotes is re-measured by the test suite.
  • Added a differential suite against a checksum-pinned MARS 4.5, comparing machine code, data segment, console output and all 32 registers. Eight of eleven programs are byte-identical; the three remaining differences are declared with a reason and a minimal reproduction case.
  • Added generated evidence reports for compatibility, MARS conformance, coverage, mutation score, benchmark and accessibility, each regenerated by one command and checked by the test suite.
  • Added a published benchmark protocol with a declared warm-up, repetition count and outlier rule, reporting medians with interquartile ranges and recording the machine each result came from.
  • Added mutation testing and bounded deterministic fuzzing of the assembler, runtime and state importer.
  • Fixed the Pipeline Lab receiving no runtime updates after the first assembly, caused by the tool reporting itself as disconnected.
  • Fixed symbolic branch targets never resolving in the timing model, which made every branch prediction report zero mispredictions.
  • Fixed a crash when importing a corrupted or absent saved runtime state, which reached the user as a blank screen.
  • Fixed the editor and the Mars Messages pane having no accessible name, and a text colour below the WCAG contrast minimum in the light theme.
  • Fixed the pinned timeline column detaching in right-to-left languages, and kept the pipeline diagram left to right so its stage order still reads forward.
  • Added an optional colour-vision-safe palette for the pipeline stages.
  • Added developer documentation: architecture boundaries, a first-contribution guide, guides for adding instructions, syscalls and devices, the runtime invariants, the versioned tool API with a worked example and a scaffold generator, and the release process.

Historical note

Some earlier releases experimented with WebAssembly acceleration and backend selection. Those entries describe their release accurately, but that subsystem is no longer present. The current runtime is JavaScript-only.
