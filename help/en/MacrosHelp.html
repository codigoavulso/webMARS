Assembler macros

Macros perform source-level substitution before normal assembly. They require extended assembler support to be enabled.

Definition and use

.macro print_int (%value)
    move $a0, %value
    li   $v0, 1
    syscall
.end_macro

li $t0, 42
print_int ($t0)

The parentheses around parameters and invocation arguments are optional. Parameters are comma-separated tokens and are replaced only as identifiers, not inside string literals.

Rules implemented by webMARS

  • A macro is identified by its name and arity, so the same name may have definitions with different parameter counts.
  • The definition must appear before its invocation. A forward reference is reported as an error.
  • Nested macro definitions are not allowed.
  • A definition ends with a line containing only .end_macro.
  • Duplicate definitions with the same name and arity produce a warning and the duplicate is ignored.
  • Labels inside an expansion are made unique for each invocation to prevent collisions between expansions.
  • Expansion is recursive, but invalid recursion and malformed invocations are diagnosed instead of silently generating code.

Constants and includes

.eqv supplies identifier substitution for named constants. .include is part of the extended assembler directive set and resolves project source where the current browser project provides it. Prefer project-relative names and keep included sources in the same project.

Macros versus pseudo-instructions

A pseudo-instruction is selected from webMARS's instruction reference and expands according to operand patterns. A macro is defined by the program and can contain an arbitrary sequence of source statements. Both are expanded before execution and may map one source line to several basic instructions.

Macro arguments are token substitutions, not typed values. A syntactically valid expansion can still produce an assembler type or range error at the invocation site.
