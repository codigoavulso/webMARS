Historia

webMARS zaczęło się jako port przeglądarki symulatora MARS 4.5 MIPS. Łączy teraz niezależne środowisko wykonawcze JavaScript, edytor, debuger, kompilator Mini-C, przepływy pracy projektów lokalnych/w chmurze i narzędzia natywne dla przeglądarki.

Obecna linia rozwoju

  • JavaScript – czas wykonania tylko. Eksperymentalna ścieżka hybrydowa/WASM została usunięta po tym, jak pomiar wykazał, że zwiększała złożoność bez wartościowej poprawy w przypadku tego obciążenia.
  • Poprawność wykonania. Najnowsze, wzmocnione w pracy porządkowanie podwójnych słów COP1, składowanie pamięci atomowej, rezerwacje sterty, LL/SC, ścisłe adresowanie, łącza z opóźnionym rozgałęzieniem, FCSR zaokrąglanie, kontynuacja wyjątków i zachowanie Stop.
  • Pełne migawki stanu. Eksport/import i krok wstecz uwzględniają teraz losowe strumienie, pliki wirtualne i kursory, standardowe wejście, argumenty programu, uchwyty obrazów i punkty przerwania.
  • Obserwowalność wydajności. Aplikacja raportuje lokalne czasy kompilacji, montażu i uruchamiania oraz szacunkowe wykorzystanie JavaScript, podczas gdy wykonywanie z maksymalną szybkością zmniejsza obciążenie prezentacji bez ograniczania stanu środowiska wykonawczego narzędzi.
  • Mini-C ewolucja. Podzbiory nauczania C0 pozostają dostępne wraz z wywołaniami C1-NATIVE, o32, ciągami bajtów, argumentami, wskaźnikami funkcji, projektami wieloplikowymi i bibliotekami zgodności.
  • Przykłady jako program nauczania. Przykłady asemblera i C są katalogowane według celu, języka i minimalnego profilu kompilatora, z wielojęzycznymi wariantami i projektami wieloplikowymi.

Linia kompatybilności

Słownictwo instrukcji, typowe wywołania systemowe, koncepcje interfejsu użytkownika i model nauczania wywodzą się z oryginału MARS projekt Pete'a Sandersona i Kennetha Vollmara. webMARS zachowuje tę linię, zastępując integrację pulpitu Java z interfejsami API przeglądarki i własnym silnikiem wykonawczym.

Zapis wersji

The webMARS → Lista zmian strona pomocy zawiera szczegółowy zapis projektu wersja po wersji. Wpisy historyczne opisują stan ich wydania; nie stanowią obietnicy, że w bieżącej wersji pozostanie eksperymentalny podsystem.

Jeśli dokumentacja i historyczny wpis dziennika zmian różnią się, pierwszeństwo mają bieżące strony tematyczne i bieżące zachowanie środowiska wykonawczego.
