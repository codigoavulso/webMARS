Sejarah

webMARS dimulai sebagai port browser dari simulator MARS 4.5 MIPS. Sekarang menggabungkan runtime JavaScript independen, editor, debugger, kompiler Mini-C, alur kerja proyek lokal/cloud, dan alat asli browser.

Jalur pengembangan saat ini

  • JavaScript-waktu proses saja. Jalur hybrid/WASM eksperimental telah dihapus setelah pengukuran menunjukkan bahwa jalur tersebut menambah kompleksitas tanpa perbaikan yang berarti untuk beban kerja ini.
  • Kebenaran waktu proses. Pekerjaan terbaru memperkuat pemesanan doubleword COP1, penyimpanan memori atom, reservasi heap, LL/SC, pengalamatan ketat, tautan cabang tertunda, pembulatan FCSR, kelanjutan pengecualian, dan perilaku Hentikan.
  • Cuplikan status lengkap. Ekspor/impor dan backstep sekarang memperhitungkan aliran acak, file virtual dan kursor, stdin, argumen program, pegangan gambar, dan titik henti sementara.
  • Observabilitas kinerja. Aplikasi ini melaporkan waktu Kompilasi, Rakitan, dan Jalankan lokal ditambah perkiraan pemanfaatan JavaScript, sementara eksekusi kecepatan maksimum mengurangi overhead presentasi tanpa membuat alat status runtime kelaparan.
  • Mini-C evolusi. Subset pengajaran C0 tetap tersedia bersama C1-NATIVE, panggilan o32, string byte, argumen, penunjuk fungsi, proyek multi-file, dan pustaka kompatibilitas.
  • Contohnya sebagai kurikulum. Contoh Majelis dan C dikatalogkan berdasarkan tujuan, bahasa, dan profil kompiler minimum, dengan varian multibahasa dan proyek multi-file.

Silsilah kompatibilitas

Kosakata instruksi, syscall umum, konsep antarmuka pengguna dan model pengajaran berasal dari aslinya MARS proyek oleh Pete Sanderson dan Kenneth Vollmar. webMARS mempertahankan garis keturunan tersebut sambil mengganti integrasi desktop Java dengan API browser dan mesin eksekusinya sendiri.

Catatan versi

Itu webMARS → Catatan Perubahan halaman bantuan berisi catatan proyek versi demi versi yang terperinci. Entri sejarah menggambarkan keadaan pelepasannya; hal tersebut bukanlah janji bahwa subsistem eksperimental akan tetap ada dalam versi saat ini.

Jika dokumentasi dan entri log perubahan historis berbeda, halaman topik saat ini dan perilaku runtime saat ini akan diutamakan.
