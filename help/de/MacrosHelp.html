Assembler-Makros

Makros führen vor der normalen Assemblierung eine Ersetzung auf Quellebene durch. Sie erfordern die Aktivierung der erweiterten Assembler-Unterstützung.

Definition und Verwendung

.macro print_int (%value)
    move $a0, %value
    li   $v0, 1
    syscall
.end_macro

li $t0, 42
print_int ($t0)

Die Klammern um Parameter und Aufrufargumente sind optional. Parameter sind durch Kommas getrennte Token und werden nur als Bezeichner und nicht innerhalb von Zeichenfolgenliteralen ersetzt.

Von webMARS implementierte Regeln

  • Ein Makro wird durch seinen Namen und seine Arität identifiziert, sodass derselbe Name Definitionen mit unterschiedlicher Parameteranzahl haben kann.
  • Die Definition muss vor ihrem Aufruf erscheinen. Eine Vorwärtsreferenz wird als Fehler gemeldet.
  • Verschachtelte Makrodefinitionen sind nicht zulässig.
  • Eine Definition endet mit einer Zeile, die nur enthält .end_macro.
  • Doppelte Definitionen mit demselben Namen und derselben Arität erzeugen eine Warnung und das Duplikat wird ignoriert.
  • Beschriftungen innerhalb einer Erweiterung werden für jeden Aufruf eindeutig gemacht, um Kollisionen zwischen Erweiterungen zu verhindern.
  • Die Erweiterung ist rekursiv, aber ungültige Rekursionen und fehlerhafte Aufrufe werden diagnostiziert, anstatt stillschweigend Code zu generieren.

Konstanten und Includes

.eqv Bietet Bezeichnerersatz für benannte Konstanten. .include ist Teil des erweiterten Assembler-Anweisungssatzes und löst die Projektquelle dort auf, wo sie vom aktuellen Browserprojekt bereitgestellt wird. Bevorzugen Sie projektbezogene Namen und behalten Sie die enthaltenen Quellen im selben Projekt bei.

Makros versus Pseudoanweisungen

Ein Pseudobefehl wird aus der Befehlsreferenz von webMARS ausgewählt und gemäß Operandenmustern erweitert. Ein Makro wird vom Programm definiert und kann eine beliebige Folge von Quellanweisungen enthalten. Beide werden vor der Ausführung erweitert und können eine Quellzeile mehreren Basisanweisungen zuordnen.

Makroargumente sind Token-Ersetzungen, keine typisierten Werte. Eine syntaktisch gültige Erweiterung kann immer noch einen Assembler-Typ- oder Bereichsfehler auf der Aufrufseite erzeugen.
