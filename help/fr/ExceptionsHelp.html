Exceptions

Une erreur d'exécution transfère le contrôle au gestionnaire d'exceptions configuré ou met fin à l'exécution avec une raison explicite. Les exceptions traitées peuvent continuer jusqu'à eret.

Flux du gestionnaire

  1. Le runtime capture Cause, EPC et BadVAddr selon le cas et entre dans le niveau d'exception.
  2. Si le code du gestionnaire exécutable existe à l'adresse configurée, normalement 0x80000180-le PC y transfère.
  3. Le gestionnaire inspecte l'état COP0, effectue sa récupération, ajuste EPC si nécessaire et exécute eret.
  4. Si aucun gestionnaire n'est présent ou si une exception se produit qui ne peut pas être transférée en toute sécurité, l'exécution s'arrête et le résultat Run signale l'exception.
Créneaux de retard. Pour une exception déclenchée dans un créneau de retard de branchement, Cause.BD est défini et EPC identifie l'instruction de branchement, et non l'adresse du créneau de retard.

Garanties d'adresse et de magasin

Les cibles d’instruction doivent être alignées sur les mots. Les magasins multi-octets vérifiés valident la destination entière avant de valider un octet, de sorte qu'une exception d'adresse ne peut pas laisser un mot partiellement écrit ou un double mot. Le mode mémoire stricte s'applique également aux opérations sur mots partiels telles que LWL et LWR.
